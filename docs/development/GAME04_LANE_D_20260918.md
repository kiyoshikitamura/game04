`src/app/legal/legalConfig.ts` の `status` は `draft`。全 Legal ページで草案表示し検索 index を禁止する。未確定値を推測で埋めず、正式確認後に施行日とともに `published` にする。

`original.title.support@gmail.com` と `www.tribe-neon.com` を GAME04 の確定値として使用しない。GAME03 の請求時開示文も無条件で転用しない。既存120日の期限・有償から交換した商品の期限継承・価格等の仕様は維持。120日だけを根拠に法的適用除外を断定しない。

## 旧素材監査

実行：`node scripts/audit_game04_legacy_materials.mjs`

出力：`docs/development/GAME04_LEGACY_AUDIT_20260918.json`

- `findings`：ファイル・行・旧ブランド/地域/キャラ/技装備名。稼働コード、原本マスター、QA、旧名対応表を分ける。
- `assetReferences`：素材 URL、静的参照元、動的参照候補。参照中・差替要確認・未使用候補を区別する。
- 旧ファイル名でも戦国画像へ中身が置換済のキャラ60体とロゴは互換パスとして保持。
- 原本マスターに旧名が残っていても表示変換層が適用されるため、即表示不具合と判定しない。
- ソースの静的参照がなくても DB や動的合成から参照され得る。未使用を断定せず削除しない。
- 新背景・ガチャ・訴求・レイド・音源の提供待ちは保持する。
- この監査は作業ツリーの時点結果。全 Lane 統合後に再実行する。DB 内のユーザー投稿は一括置換しない。

## 不具合対応手順（#189）

1. 開発中の報告は、このゲームを案内した既存の連絡先で受ける。正式窓口の値が確定したら contact ページの同じ導線へ接続する。
2. 対象ゲーム「戦国姫艶武」、環境 Preview、プレイヤーID、日時（タイムゾーン付き）、画面・操作、期待結果・実結果、端末/OS/ブラウザ、必要なら注文番号を整理する。パスワード・認証コード・カード番号を要求しない。
3. 当時の Preview URL と commit SHA を記録する。調査先は GAME04 DB `lrgyllgzcdcphlbmkknc` のみ。GAME03 で再現操作しない。
4. 最初は読取調査。購入の注文・付与・受取を分け、付与済み分を重ねて補填しない。探索/戦闘の receipt/replay を使って照合する。
5. 同じ版の Preview で再現・修正。型/ビルドと当該操作を確認し、項番・修正 SHA を残す。
6. 修正を Preview へ配信して状況を更新する。データ復旧・返金・補填が必要なら処置と対象を別記録し、UI 修正と混ぜない。
7. Production 公開、GAME03 書込み、プレイヤーデータの一括削除は本手順の対象外。

購入が反映されない場合は再購入を繰り返さない。ログイン問題では画面を残し、「はじめから」やブラウザデータ削除の前に報告する旨を画面にも記載。
