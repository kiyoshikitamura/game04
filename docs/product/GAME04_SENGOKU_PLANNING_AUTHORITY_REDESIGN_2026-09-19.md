# 6. キャラクターパラメータ

キャラクターの基本パラメータは以下を基本とする。

- HP
- ATK
- DEF
- LUK

**SPDは廃止する。**

行動順は速度パラメータでは決めず、デッキ編成順を使用する。

## 6.1 HP

HPはキャラクター個別とする。

戦闘不能になったキャラクターの行動順は単純SKIPとする。
蘇生した場合は、次回の自分の行動順から復帰する。

## 6.2 LUK

LUKは各キャラクターが個別に持つ。

主な役割：

- パーティ全体のドロップ補正に利用
- 当該キャラクターのSP獲得量に利用
- 当該キャラクターのBURST発動率に軽い補正を与える

ドロップ補正はパーティ全体へ適用する。
BURST補正は行動キャラクター本人のLUKのみを使用する。

# 13. バトル

GAME04は**完全オートバトル**を基本とする。

ユーザーは戦闘中の操作ではなく、

**戦闘前の編成・行動順・スキル構成**

にゲーム性を持たせる。

オートであるため、戦闘では「何が起きたか」「なぜその行動になったか」が視覚的に理解できることを重視する。

## 13.1 バトル画面

GAME03の横方向パーティバトル表示から変更する。

縦画面内で、

- 上部：Enemyを大きく表示
- 下部：Player PartyのHP・状態・行動状況を明確に表示

とする。

## 13.2 Wave制

ステージバトルはWave制を基本とする。

例：

Wave1 → Wave2 → Wave3 → Boss

Waveをまたいでパーティ共通SPを保持し、道中でのSP獲得・消費とBoss到達時の残量が攻略性につながる設計とする。

## 13.3 行動順

SPDは使用しない。

味方の通常行動順は**デッキ編成順**とする。

ユーザーはキャラクターの並び順そのものを、

- SP生成
- バフ
- デバフ
- 高火力
- BURSTとの連携

を考慮して設計する。

戦闘不能キャラクターの順番はSKIPする。
蘇生後は次回の自分の順番から復帰する。

## 13.4 パーティ共通SP

SPはキャラクター個別ではなく、**パーティ共通リソース**とする。

SP初期値は原則0スタートを第一候補とする。
満タンスタートとの比較は実機検証対象とする。

SP獲得量の基本式：

**SP獲得量 =（キャラクターの与ダメージ / 回復量 / バフ・デバフ規定値 × 当該キャラクターLUK）÷ 補正係数**

- ダメージキャラは与ダメージでSPを生成
- ヒーラーは回復量でSPを生成
- バフ / デバフは効果ごとに設定した規定値でSPを生成
- 補正係数はSP最大値の桁数・数値バランスに応じて後日FIX

## 13.5 通常時のスキル発動

スキルはランダム発動を基本としない。

通常行動時は以下の順で判定する。

1. 発動条件を満たしているスキルを候補化
2. 現在SPで発動可能なスキルに限定
3. 消費SPが大きいスキルを優先
4. 同消費SPならスキルスロット順
5. 発動可能スキルがなければ通常攻撃

この優先順位は**暫定FIX**とし、実機プレイで違和感がある場合は変更可能とする。

作戦・ユーザー指定AI等の追加システムは入れない。

## 13.6 ターゲットルール

単体攻撃・単体スキルの対象は各スキル側にTarget Ruleを持たせる。

候補：

- HP最低
- HP最高
- 前列
- ランダム
- 特定状態
- その他スキル固有条件

通常攻撃にも共通Target Ruleを設定する。

Target Ruleは**暫定FIX**とし、実機プレイで違和感がある場合は変更可能とする。

## 13.7 BURST

SPが満タンになった場合、**SPを満タンにした行動キャラクター本人が直後にBURST抽選**を行う。

BURST発動率：

**BURST発動率 =（キャラクターLv ÷ 2）+（当該キャラクターLUK ÷ 補正係数）**

- 最大発動率：80%
- LUK補正は軽い補正とする
- 補正係数は数値設計時にFIX

BURST発動時、そのキャラクターは通常時にはできない**スキル連打モード**へ入る。

BURST中：

- 同一スキルの連続使用を許可
- スキルSP消費量を通常時の50%とする
- 発動可能なスキルを連続して使用する
- 「大技 → 大技 → 大技」のような通常時には起こらないワンサイド展開を演出する

BURST終了条件：

- 共通SPが枯渇
- またはBURST中の行動回数が5回に到達

いずれか早い方で終了する。

終了後は通常のデッキ編成順へ復帰する。

BURSTは、オートバトルにおける確率的な上振れ・爽快感・演出上の山場を担当する。

## 13.8 バトル設計原則

- 基本行動とスキル発動は因果関係を理解できること
- SP増減を視覚的に確認できること
- スキル発動理由・SP不足による通常攻撃への切替を理解できること
- BURSTは通常戦闘と明確に異なる演出を行うこと
- テンポを優先しつつ、誰が何をしたか追えること
- 戦闘結果からデッキ変更の仮説を立てられること

## 13.9 エネミー基本構成

Enemy Partyは**1〜3体、最大3体**とする。

各Enemyは以下を個別に持つ。

- HP
- SP
- 行動カウント
- 行動順
- スキル構成
- Target Rule
- バフ / デバフ / 回復 / 蘇生
- 死亡時効果
- フェーズ条件

敵側のスキル・Target Rule・バフ・デバフ・回復・蘇生は、原則として味方側と共通ルールを使用する。

敵専用の別系統ルールを増やさず、同じスキルシステム上でEnemy固有の挙動を設計する。

## 13.10 エネミー行動カウント

各Enemyは個別の行動カウントを持つ。

- 初期値はEnemyごとに設定
- 3固定ではない
- 味方側の**1アクションごとに1減少**
- カウントが0になったEnemyは、その時点で割り込み行動を行う
- 行動終了後は、そのEnemyに設定されたカウントへ再設定する

表示上は残りカウントを明確に可視化し、

**3 → 2 → 1 → 0 → Enemy Action**

のように、次にいつ敵が動くか理解できるUIとする。

複数Enemyが同時に0へ到達した場合は、敵側に設定された**行動順**で処理する。

この行動ブロック / 割り込み方式は**暫定FIX**とし、実機で認識負荷が高い場合は調整可能とする。

## 13.11 エネミーSP

Enemy SPは各Enemyが個別に持つ。

### 初期状態

Enemyは**SP最大値から戦闘開始**する。

戦闘開始直後から敵の大技を警戒させ、緊張感を作る。

### SP回復

Enemyは主に**被弾によってSPを回復**する。

これにより、

味方が行動
→ Enemyへダメージ
→ Enemy SPも蓄積
→ 次のEnemy Actionが強くなる

という因果を作る。

Enemy SPの最大値、被弾時のSP換算式、各スキル消費SPは数値設計時にFIXする。

## 13.12 エネミースキル行動

Enemy Action時は、そのEnemy自身のSPを消費して発動可能なスキルを連続実行する。

基本思想は味方BURST時に近いが、Enemy側にはBURST状態そのものは持たせない。

Enemyのスキル構成により、行動回数・行動内容を設計する。

例：

- 高SP大技1つ → 実質1回行動
- 低SP小技2つ → 2回行動
- 低SP小技3つ → 3回行動
- 強Boss：低コスト大技 → 小技
- 強Boss：大技 → デバフ → 小技

これにより、別の行動回数システムを作らず、SPコストだけでEnemyの連続行動を設計できる。

### Enemyスキル優先順位

通常時の候補ルールは以下とする。

1. 発動条件成立
2. SP充足
3. 消費SPが大きいスキルを優先
4. 同消費SPならスキルスロット順

この優先順位は**暫定FIX**とし、実機プレイで違和感がある場合は変更可能とする。

## 13.13 Enemy Target Rule / 支援行動

Enemyの攻撃・回復・バフ・デバフ・蘇生も、味方側と同じTarget Ruleの仕組みを利用する。

Enemy専用の対象選択システムは原則作らない。

これにより、

- 単体攻撃
- 全体攻撃
- HP最低対象
- HP最高対象
- 特定状態対象
- 味方Enemy回復
- 味方Enemyバフ
- Player Partyへのデバフ
- 蘇生

などを共通システム上で実現する。

## 13.14 戦闘不能 / 死亡時効果

Enemyが戦闘不能になった場合、

- そのEnemyのSPは消滅
- そのEnemyの行動カウントは消滅
- 以後の行動対象から除外

とする。

ただし**死亡時効果**は残す。

死亡時効果はEnemyだけでなくPlayer Characterにも共通で持てる仕様とする。

用途例：

- 自爆
- 死亡時全体ダメージ
- 死亡時バフ
- 死亡時デバフ
- 自動蘇生
- 味方蘇生
- 死亡時SP変動

## 13.15 Bossフェーズチェンジ

Bossにはフェーズチェンジ機能を持たせる。

主なトリガー候補：

- HP一定以下
- 特定スキル使用後
- 特定Wave到達
- 一定行動回数
- 特定状態付与

フェーズチェンジによって変更可能な要素：

- スキル構成
- スキル消費SP
- 行動カウント
- Target Rule
- バフ / デバフ
- SP回復効率
- 演出
- 外見 / 表示状態

これをBossバリエーションおよび高難度攻略の主要要素として利用する。

## 13.16 Enemy BURST

Enemy側には**BURSTを持たせない。**

Enemy Actionそのものを、個別SPを消費した連続スキル行動として設計することで、Player側BURSTとの差別化を維持する。

# 14. レイド

レイドはGAME04のエンドコンテンツ兼ソーシャル接続として維持する。

GAME04では3種類のレイドを**段階解放ではなく並列に共存するエンドコンテンツ**として設計する。

3種類の役割は以下とする。

## 14.1 エンカウントレイド

役割：

**希少性 / 瞬発的な多人数参加**

通常クエスト等のプレイ中に低確率でレアレイドへエンカウントする。

基本仕様：

- 希少発生
- 短時間開催
- 目安：約1時間
- 1回の発見につき1戦型
- 非同期で複数ユーザーが共通HPを削る
- 攻略性よりも「逃す前に倒す」ことを優先
- 参加人数が多いほど討伐しやすい
- メタルスライム型の希少報酬コンテンツとして扱う

報酬方針：

- 育成原資3系統のうち1種類に特化
- 他コンテンツでも入手可能な原資とする
- エンカウントではその1原資を**超大**で供給する
- 限定必須報酬にはしない

敵ごとに特化原資を変える方式も採用可能とする。

## 14.2 任意解禁レイド

役割：

**強さのトップライン / じっくり攻略する高難度共有エリア**

ユーザーが鍵・チケット等を使用して任意に解禁する。

実態としては「期間限定の共有攻略エリア」に近い。

基本仕様：

- 開催期間：約3日
- Lv制で進行
- ボス撃破ごとに次Lvが解放
- Lvが上がるほど難易度が上昇
- 非同期で共通HPを削る
- 1戦1戦は各ユーザーが自分のデッキで戦い、勝敗を持つ
- 先行者は高Lvで壁に当たり、後続参加者の合流を待つ構造
- 最終Lvボス撃破または時間切れで終了

### チェックポイント方式

途中参加はチェックポイント方式とする。

- 一定Lvごとにチェックポイントを設定
- 例：5Lvごと
- 共有進行がLv14の場合、後続参加者は直近通過済みチェックポイントのLv10から参加
- 共有進行がLv10の場合はLv10から参加

チェックポイント間隔の具体値はレイド数値設計時にFIXする。

報酬方針：

- 育成原資3系統のうち2種類に大小を付けて供給
- 他コンテンツで取得不能な必須原資は置かない

## 14.3 ギルドレイド

役割：

**集団対集団の期間競争 / ギルドランキング接続**

短期間の開催期間内に、固定されたギルドメンバーでどこまで進めるかを競う。

基本仕様：

- 短期開催
- Lv進行型
- ボス撃破ごとに次Lvへ進む
- 各メンバーは個別に自分のデッキで攻略
- 各々の攻略にはスピード感を求める
- ギルド全体の成果を集計
- ギルドランキングへ接続

### 人数差補正

ギルド人数そのものがランキング結果を決めないよう、

**ランキングスコアは上位N人を集計する。**

ただし、

- 参加自体は全メンバー可能
- 個人プレイ・個人報酬も全員有効
- ランキング集計のみ上位N人を採用

とする。

Nの具体値はギルド最大人数と実アクティブ率を見て後日FIXする。

報酬方針：

- 育成原資3系統のうち2種類に大小を付けて供給
- ランキング報酬を接続可能
- ギルド参加をゲーム進行上の必須条件にはしない

## 14.4 3種レイドの並列関係

3種レイドは以下の異なる欲求を担当する。

| コンテンツ | 主目的 | 時間軸 | 人数価値 | 攻略テンポ |
|---|---|---|---|---|
| エンカウントレイド | 希少敵を逃さず討伐 | 約1時間 | 非常に高い | 瞬発 |
| 任意解禁レイド | 強さの限界へ挑戦 | 約3日 | 中〜高 | じっくり |
| ギルドレイド | 集団対集団の競争 | 短期 | 非常に高い | 高速 |

これらは段階コンテンツではなく、同時に存在するエンドコンテンツとして設計する。

# 23. 基本ゲームサイクル

GAME04の基本サイクルは、シングル攻略を土台として成立させる。

## 23.1 シングル基本サイクル

クエストへ挑戦
↓
敵に敗北 / より良い攻略を目指す
↓
敵の特徴を確認
↓
キャラクターを育成
↓
スキルを育成
↓
装備を育成
↓
デッキを変更
↓
再挑戦
↓
ステージ突破
↓
次のステージへ

ゲームの中核は、

**観察 → 仮説 → デッキ変更 → オートバトル → 結果確認 → 再調整**

とする。

## 23.2 クエスト更新サイクル

通常クエストは各エリアごとに攻略テーマを設定する。

例：

- 属性テーマ
- 状態異常テーマ
- SPDテーマ
- DEFテーマ
- 特定ロールテーマ

初期は10エリア、約70〜80ステージを基本とする。

ローンチ後は、

**月次で新シーズンエリアを追加する。**

月次追加は以下をセットで行う。

- 新エリア
- 新攻略テーマ
- 新キャラクター
- 新スキル
- 新装備

これにより、シナリオ大量制作ではなく、攻略環境の更新によって継続リズムを作る。

特定キャラクター必須にはせず、複数の攻略解を持たせる。

## 23.3 育成原資サイクル

育成原資は大きく以下の3系統とする。

- キャラクター育成原資
- スキル育成原資
- 装備育成原資

シングルプレイだけでも3系統すべてを獲得可能とする。

基本思想：

**シングル = 小 × 3**

レイド参加時は、特定原資の取得効率が上がる。

各レイドの報酬は「限定品」ではなく、原則として**効率差**で差別化する。

例：

- エンカウント：1原資を超大
- 任意解禁：2原資を大小
- ギルド：2原資を大小

具体的な割り当ては経済設計時にFIXする。

0を作らず、「このコンテンツを遊ばないと育成不能」という構造にしない。

## 23.4 エンドコンテンツ分岐

シングルの基本サイクルから、3種類のエンドコンテンツへ並列分岐する。

**希少性**
→ エンカウントレイド

**強さのトップライン**
→ 任意解禁レイド

**集団競争**
→ ギルドレイド

各レイドで得た育成原資は、再びキャラクター・スキル・装備の育成へ戻る。

全体循環：

クエスト攻略
↓
育成
↓
デッキ構築
↓
高難度攻略
↓
3種レイド
↓
育成原資獲得
↓
さらに育成
↓
さらに高難度へ

この循環により、

**シングルで定着し、育成成果をエンドコンテンツで試し、ソーシャルへ自然に接続する**

構造を作る。

# 24. 設計判断の原則

GAME04では、

**「GAME03にあるから残す」**

を判断基準としない。

すべてのゲーム機能について、

**デッキ構築と攻略の面白さに寄与するか**

を優先判断軸とする。

一方、設定・お知らせ・プレゼントBOX・認証・購入履歴等の共通運営基盤は再利用する。

整理すると、

**残すもの = 共通技術 / 運営基盤**

**作り直すもの = ゲーム性 / 育成 / バトル / コンテンツ / 経済設計**

とする。
