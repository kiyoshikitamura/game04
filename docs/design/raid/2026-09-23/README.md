## 最重要：誰のレイドか
ボスと開催者は別情報。一覧・詳細とも開催者の顔アイコン＋「開催者」＋ユーザー名を常時表示する。
レイドの開催者IDに対応するユーザー情報へ接続する。閲覧者や最後の参加者で代用しない。モックの「さくら」「あかね」は仮名で、本実装へ固定しない。QAでは開催者と閲覧者が異なる場合も確認する。
既存経路に開催者情報がなければ必要な接続を行う。正式な開催者の定義・IDを確認できない場合は不足として報告し、架空データで隠さない。

## 画面構成
### 01 レイド一覧
共通Header、レイド見出し＋更新、均等な3タブ（すべて／エンカウント／領土侵攻）、残り時間順表示。
背景＋大きなボスの横長カードをモックと同じ比率で再現。種別・参加状態、ボス名／Lv、属性／難度、開催者、HPゲージ、時間・人数、続きへをモックの位置で配置する。
人物を小さな添え物にせず、単色背景＋テキスト羅列へ戻さない。
下部の宝箱付き「終了したレイド・未受取報酬」と既存の結果・受取機能を維持する。

### 02 レイド詳細
戻る、背景＋大きなボス、種別・難度、ボス名／Lv／属性、開催者、HP、時間・人数の順。
多重枠を付けず、広い不透明帯で背景を隠さない。
敵情報／参加者／報酬／救援はモックの2列×2行と図柄を再現し、既存機能・Dialogへ接続する。

### 03 詳細・下部
02の同一詳細ページの下方を示す。新ページやタブは増やさない。
小さなボス／開催者／HPの表示はスクロール時のコンパクトな文脈表示として再現する。大きなHeroと重複して常駐させない。
自分の貢献は、累計ダメージの大きな数字、挑戦数・勝利数・直近状態、丸い報酬資格進捗、参加時の共通進行をモックどおり整理する。
3勝・行動力5等は表示例。正式条件・数値を参照し、デザイン都合で変更しない。
赤い「挑む」CTAとコスト表示を再現する。Footerとの重なりを避け末尾まで到達可能にする。

## 素材・不足
正式素材をまず照合する。不足アイコンは制作対象として扱い、アイコン無し・絵文字・別用途素材・GAME03素材・文字だけのボタンで済ませない。
ASSET_REQUIREMENTS.mdに既存採用元と不足を区別して記載し、制作に必要な図柄・寸法・形式・状態を具体化する。未確認を不足確定としない。
ユーザーが不足分を制作する予定であり、実装担当が未承認素材を勝手に生成する指示ではない。供給待ちは記録して他部分を進め、仮素材のまま完成と報告しない。
モック人物・背景は検討表現。正式武将・背景・属性画像を使い、構図・占有率・重心を忠実に合わせる。新しい武将の姿や属性体系を定義したものではない。正式素材で再現できない差分は明示する。
開催者顔は顔が見切れないクロップ。カードは枠の開口部内へ背景・人物を収め、縦横比と元素材の描画範囲を維持する。

## 寸分違わないための実装・検証
- 最初に同梱PNGを画像として開き、各パネルと全体を確認する。
- ボード見出し・外余白・仮名注記はゲームUIに含めない。
- 各画面の幅に対する領域・図柄・余白の比率を測って再現する。任意の再配置や装飾省略をしない。
- 375／390pxでも構成と可読性を維持。文字を極端に縮めたりPNGを画面全体に貼ったりして合わせない。
- 本文は承認済みNoto Sans JP、見出しは共通書体。生成された字形誤差を再現せず正しい日本語・正式値を使う。
- 画像・バッジ・名前・Lv／能力値を独立領域へ配置。固定高やCSS競合による重なりを排除。共通部品と実ページ両方で確認する。
- 同幅・同状態でモックと実画面を横並び比較し、配置・サイズ・余白・装飾の差を自律修正する。動的データと正式素材に由来する差は記録し、説明なく免除しない。
- 一覧3フィルタ→詳細→関連Dialog→挑戦導線、詳細下部、終了／未受取報酬を確認。共通読み込み・操作抑止・非活性・スクロールを維持する。
- Build／Typecheck／HTTP200だけで視覚完了としない。
- 実装SHA、固定Preview、Deployment、比較画像、素材対応／不足表、検証記録をGit保存する。実装済み／供給待ち／未検証を分けて報告する。
ページ全体を一括で仕上げる。細かな工程承認を増やさない。最終ビジュアル受入はユーザー判断。
