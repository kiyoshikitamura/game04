# GAME04 共通画像合成ルール厳格化・クエスト再指摘一括修正
基準SHA: 46377bfff487f2cfbc46d8054e55b05b400acc2d
対象: クエストの共通表示部品と全利用箇所。今回は指示書のみの更新。
最新ユーザー指摘を優先する。前回の「全指摘対応済み」は撤回し、以下の再指摘を未解消として扱う。
部品別／画面別の中間承認は不要。担当内で修正・比較を完結して一括報告する。

## 1. カード合成の共通ルール（最優先）
### 形状と領域
- 正式フレーム画像の外寸と「内側の開口部」を別に定義する。画像ファイル四辺＝カードの開口部ではない。
- フレーム自身に含まれる透明外周も考慮する。背景をフレーム画像全体の矩形いっぱいに置くだけの実装は禁止。
- 合成順は、内側開口部に限定した背景→人物→正式フレーム。属性・レアリティ・名前・Lv等の情報は画像の外の独立領域。
- 背景は開口部の輪郭に合わせてクリップ／マスクし、外側へ一切出さない。カード親へのoverflow:hiddenだけで合格扱いにしない。
- フレームは元の縦横比を保持する。横伸ばし・縦伸ばしで合わせない。
- 開口部が矩形なら素材ごとに測定した内側余白、非矩形ならその輪郭に対応する表示用マスクを使用。曖昧な共通パーセントを推測して全フレームへ適用しない。
- 背景にはcoverを使ってよいが、人物へcoverや拡大トリミングを適用しない。

### 人物
- カード用カウボーイショットに元から描かれている下端まで表示する。足全体がない素材に足を要求する意味ではない。
- 頭・手・武器・描画済みの下端を追加で切らない。透明余白と実際の人物描画範囲を区別し、その描画範囲を開口部内に収める。
- 中央配置と大きさを両立し、人物を大きくするためにフレームやクリップで下端を隠さない。
- バッジを人物に重ねて下端を隠す配置も禁止。

### 再利用
- N/R/SR/SSRごとのフレーム開口部定義を一箇所に集約。出撃準備・キャラ詳細・確認ページで同じ合成部品を使用する。
- 利用側CSSから背景サイズ、人物のtransform、クリップ、フレーム比率を独自に上書きしない。用途差は共通部品の明示的なサイズ設定で扱う。
- 新しい似た部品の乱立ではなく、現在の部品と競合CSSを修正する。
- 画像を改変・再生成して辻褄を合わせない。

## 2. 素材の採用条件
- レアリティは今回ユーザーからGAME03素材と指摘された。現在使っている旧画像は採用不可。
- ファイルが存在する、HTTP200、名前がrarityである、という理由でGAME04正式素材と判断しない。
- 正式素材の対応表・出自・実画像を照合する。GAME04用がなければ担当者への不足アラートを上げる。
- 不足アラートにはN/R/SR/SSRの不足範囲、必要用途、確認した候補パス、旧素材を不採用にした理由をまとめる。これは開発報告上のアラートであり、プレイヤー向けエラーダイアログではない。
- 不足を旧素材、文字枠、生成画像で黙って補わない。素材不足箇所は未完了と明示し、残りの作業は続行する。
- 正式属性画像は1回のみ表示し、属性文字の二重表示は戻さない。レアリティ・属性はカードの下に並べ、画像と干渉させない。

## 3. エリア背景と文字（IMG_2748・2749）
- エリア一覧とステージ一覧上部の見出しに残る、横幅ほぼ全体の黒／濃色ベタ面を除去する。
- テキスト要素自体の背景を透明にする。章・エリア名のテキスト領域は必要な内容と最小限の余白に限定する。
- 背景画像の上に局所的な半透明グラデーションや文字影を使う。暗い不透明長方形で絵を覆わない。
- 親だけでなく子要素、疑似要素、グローバルCSS、!importantを含む実際の適用スタイルを確認する。
- 合格条件: 文字の背後にも背景が見え、エリア間の絵の違いが通常倍率で分かる。不透明な帯が残れば不合格。

## 4. ステージ番号と文頭（IMG_2749）
- 番号メダリオン、本文（名前・行動力）、状態バッジを独立したレイアウト領域にする。
- 番号の枠・影を含む右端と本文左端の間に最低8 CSS pxの間隔を確保する。
- absolute配置した番号の上へ本文が流れる構成を解消する。paddingの局所上書きだけで済ませず最終適用レイアウトを確認する。
- 375/390px、1-1だけでなく10-10、長い名称でも重ならない。必要時は本文を折り返し、文字を極小化しない。
- 正式名称未定義65件の解決と、レイアウトの不具合解消は別。未定義を理由に重なりを残さない。

## 5. ボス表示（IMG_2750）
- 見出しを「ステージボス」に統一。「最終Waveの代表ボス」は使わない。
- 属性バッジをLv・名前と同じ情報グループ内へ隣接配置する。左右どちらであっても画面端へ孤立させない。
- 画像では名前が左、属性が右端へ離れている。左右の指定よりも「名前の近くにまとめる」というユーザー意図を優先する。
- 最終WaveからLv降順、同LvはHP降順、完全同値は元順で1体選ぶ既決ルールは維持する。戦闘編成を変更しない。
- 背景＋ボス大写し、Lv・名前、HP/ATK/DEF、スキル（ない場合「無し」）の既決内容を維持。

## 6. 完了判定・報告
- 単体部品確認だけでは完了にしない。実際のクエスト利用経路で、出撃準備と詳細の両方を確認する。
- 375px/390pxで全レアリティのフレーム、体型や武器が異なる代表画像を確認。正規プレイデータは改変せずQAの読み取り専用fixtureを使ってよい。
- 比較証拠は全画面に加え、フレーム四辺と人物下端が分かる切り出しをGit保存。使用した正式枠・背景・人物のパスと開口部定義を記録する。
- 各指摘に「解消／素材不足／仕様未確定／未検証」を付ける。背景のはみ出し、下端欠け、旧バッジ、番号重なりが残れば解消としない。
- Typecheck/Build成功や画像HTTP200は視覚合格の代わりにならない。
- 修正した実装SHAと配信SHAを一致させ、固定Previewの同じ画面で再指摘箇所が消えたことを確認してから報告する。
- 差分を確認できない場合は未検証と報告し、ユーザーに同じ発見を繰り返させない。
- 既存の未確定事項（65件の正式名称・ヒント、報酬種別照合結果、明智光秀素材）も消さずに併記する。
- 完了時にCommit／Branch／固定Preview／Deployment／比較画像／検証記録／不足アラートをGitリンクで一括報告する。
数値・Battle Rule・Economy変更、Production公開、mainマージ、GAME03変更、未承認素材生成は行わない。
