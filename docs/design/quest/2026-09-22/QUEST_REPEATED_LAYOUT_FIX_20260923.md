## 2. ステージ番号と文頭：重なりが残る（IMG_2770）

- 「ステージボス」、名前横の属性、Lv・HP/ATK/DEF・スキル、代表1体の選定規則を保持。

## 4. 出撃前：キャラ画像と名前の重なり（IMG_2772）
- 合成画像、画像の下の属性等、名前、Lv/HPを、それぞれ通常フローの独立行で確保する。
- 合成画像の実際の高さを親要素にも反映する。古いheight:98pxやflex-basisに画像だけがはみ出す状態を解消する。
- 名前は画像・フレーム・バッジの描画範囲より下に置き、最低4 CSS pxの間隔を確保。名前にフレームがかからない。

## 5. キャラ詳細：約90%への縮小と余白整理（IMG_2773・2774）
- 合成済みカード画像（人物・背景・正式枠を一体で）を、今回の実機表示に対し幅・高さとも約90%に縮小して中央配置。
- transform:scale(.9)だけで元の占有領域を残す方法は使わない。width/max-width等でレイアウト上の占有寸法も縮める。
- 人物だけ縮めて背景・枠との関係を崩さない。今回改善した開口部合成、比率維持、描画下端を保持。
- 「くノ一の詳細」ヘッダーから画像上端までの過剰な余白を削る。古いpadding-topやfigureの既定margin、画像の透明外周も点検。
- 目安: Dialog本文上端〜可視フレーム上端12〜16 CSS px、フレーム下端〜名前8〜12px。透明画像の外寸ではなく可視部分で評価する。
- 名前・属性/Lv・能力値・スキルの間も共通余白へ揃え、不必要な空白で下部情報を押し出さない。
- スクロール自体は禁止しない。初期表示が巨大画像と空白だけにならず名前付近まで見え、末尾のスキルと閉じるCTAに確実に到達できるようにする。
- 短い画角でもDialogヘッダー・フッターを保持し本文をスクロール可能にする。文字や能力値を縮小して詰め込まない。
