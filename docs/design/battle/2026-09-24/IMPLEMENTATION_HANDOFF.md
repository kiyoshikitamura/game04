## 1. 依頼・目的

添付の承認モックを基準に、既存の戦闘機能・正式データ・進行状況を保持して、バトル画面のUIと演出を仕上げてください。

前スレッドは会話長の制限で終了したため、本書から継続する。静止画配置だけの実装ではなく、戦闘イベントに接続された演出まで対象とする。本陣・武将・出陣・侵攻などの別スレッドと並走する。

表示実装・戦闘イベント接続・独立検証はサブエージェントで分担し、親担当が統合する。ユーザーを差分発見・修正指示の担当にせず、担当側で全体照合・修正・再検証まで行う。

本書は今回の添付画像と会話で確認できた要件を整理したもの。現行ソース・最新ブランチ・配信状態は本書作成時には未確認。過去の実装済み報告をそのまま最新の完了証拠にはしない。

## 3. 確定した表示方針

| 項目 | 指示 |
|---|---|
| AUTO | オート戦闘のみなので表記不要。元の位置へSKIPを配置 |
| 上部操作 | モックのWAVE・倍速・一時停止・SKIPの配置を基準とし、実際の操作に接続 |
| 背景 | 落ち着いた夕暮れの城郭。背景の情報量・彩度・明度を抑え、人物・数値・演出の視認性を優先 |
| 意匠 | 黒・金を基調とする既存の戦国姫艶武の世界観。枠・装飾・文字・間隔をモックへ合わせる |
| 敵 | 中央と左右の立ち絵、属性・Lv・名前・HPバー・現在HP／最大HP・行動までの残数を表示 |
| 共通SP | 味方カード列の上にバーと現在値／上限値を表示。右側にBURST |
| 味方 | 下部に5人のカード列。順番、顔、名前、Lv、HP値とバー、状態欄、スキル欄を表示 |
| 行動中 | 該当カードの枠強調と「行動中」を、実際の行動者に合わせて切り替える |
| 状態欄 | 味方のバフ・デバフ表示を維持。残りターン等の数値は既存状態データの意味に合わせる。多数時は件数を表示 |
| スキル命中 | 対象上の命中エフェクト・ダメージ数値と、下部の使用者／技名表示を接続 |
| BURST | BURST表記を維持。発動者の大きなカットイン、暗転・光の演出、名前表示を実イベントに接続 |

SKIPの表示・使用可否は既存のモード別制御に従う。非表示制約のある戦闘まで一律に開放しない。敵人数・編成は正式な戦闘データを優先し、モックの3体へ固定しない。

## 4. 着手時の確認と並走範囲

1. リポジトリの作業規約と最新成果を確認し、専用ブランチ／作業領域を確保する。基準SHAと他担当の変更範囲を記録する。
2. 既存の戦闘本体、再生イベント、通常攻撃・スキル・BURST・リザルト、各画面からの起動経路を確認する。現行構造を活用し、見た目のために戦闘計算を作り直さない。
3. 出陣・侵攻・共闘など、共通バトルUIを利用する経路を一覧化する。各モードの差を保持する。
4. 最大6Wave対応、敵の開始SPとSP上限の分離について、既存成果の包含と表示接続を確認する。モックのWAVE 2/3やSP 240/400で上書きしない。
5. 他担当が進める本陣・武将・出陣・侵攻の画面変更、クローズ済み共闘の成果を保持する。共通コンポーネントを触る際は担当と範囲を調整する。

このタスクで能力値、報酬、ガチャ、育成、SP消費量・増加量・BURST発動条件などのゲームルールは再設計しない。未確認の仕様は既存の正本・実装で確認し、勝手に補わない。

## 5. 演出と実データの接続要件

### 通常攻撃・スキル

- 既存イベントの行動開始→対象確定→攻撃／詠唱→命中→結果反映→演出解除→次行動の流れを保つ。
- 行動者のカード強調、敵味方の対象、技名、命中エフェクト、ダメージ数値、HP変化を同じ戦闘イベントへ接続する。
- ダメージ演出だけを先に流してHPが後からずれる、別対象のHPが減る、前行動の技名が残る状態を防ぐ。
- 多段・全体攻撃、回復、ミス、クリティカル等は存在するイベントに従い処理する。新たな戦闘ルールは追加しない。
- 死亡・退場、状態付与／解除、保護解除、割込みなど既存イベントを欠落させない。内部識別子をそのまま表示しない。

### BURST

- 発動可否・発動者・SP消費と結果は既存の正規処理を利用する。装飾されたボタンだけで完了にしない。
- モックを基準に専用カットインとBURST文字を表示する。背景暗転は演出の間だけ行う。
- カットイン→命中→HP／SP／状態更新→カットイン解除の順序を実イベントと整合させる。
- カットインが命中表示を隠す、発動者を取り違える、終了後に操作を塞ぐ状態を防ぐ。

### 状態表示

- 付与・残りターン更新・解除を再生時点の状態に合わせる。戦闘終了時の状態を最初から表示しない。
- アイコンと数値の対応を既存仕様で確認する。モックの「2」「3」「+2」を一律にスタック数として解釈しない。
- 多数時もカード幅を崩さず件数を表示する。既存の詳細確認手段がある場合は保持する。

### 再生制御・Wave・結果

- 倍速、一時停止・再開、SKIPと演出タイマーを整合させる。一時停止中に次行動やHP更新だけが進行しないようにする。
- SKIP時は残存演出を解除して正しい結果へ進める。戦闘や報酬処理の二重実行を防ぐ。
- Wave切替時に敵・HP・状態・カットイン・行動中表示を適切に更新する。前Waveの表示を残さない。
- 最大6Waveを含む実データで動作し、最終Waveから勝敗・リザルト・元の進行経路まで接続する。
- 画面離脱・再戦・再表示時に古いタイマーや演出が後から発火しないようにする。

## 6. 素材と画面品質

- 正式な既存立ち絵・顔画像・状態アイコン・スキル画像を優先する。承認モック全体を背景画像として貼って完成扱いにしない。
- 背景・金枠・BURST文字・命中エフェクト等の不足を先に一覧化する。画像素材とCSS等で再現する範囲を整理し、既存の演出素材を活用する。
- 人物の顔、HP表示、下部5人のカードと状態欄がスマートフォン幅で読めるようにする。ノッチ・セーフエリア・ブラウザの表示領域変化を考慮する。
- 背景の描き込みや常時発光を増やして情報量を上げない。通常時は落ち着かせ、命中・BURST時に必要な強調を加える。

## 7. 分担と検証

| 担当 | 主担当範囲 |
|---|---|
| 親担当 | 基準確定、共有ファイルの調整、統合、差分確認、Git保存、専用Preview、最終報告 |
| 表示担当 | 配置、背景、敵情報、味方カード、SP／BURST、レスポンシブ、素材適用 |
| 接続担当 | 戦闘イベント、命中同期、状態更新、カットイン、再生制御、Wave／結果遷移 |
| 独立検証担当 | モック照合、実再生の確認、差分指摘、修正後の再確認 |

共有ファイルの無調整な同時編集を避ける。表示と接続の境界を先に決める。静止画のQAだけを通して実ゲーム経路を未接続のまま完了にしない。

### 必須受入

- 通常戦闘・スキル命中・BURSTの3状態を、同一のスマートフォン表示幅でモックと照合する。
- 3状態の実再生画像または短い動画を残し、命中・ダメージ・HPの同期とカットイン解除を確認する。
- 行動中表示、バフ／デバフの付与・更新・解除を確認する。
- 倍速・一時停止／再開・SKIP後に表示や進行が破綻しないことを確認する。
- 最大6Wave、敵SPの開始値／上限値、最終Waveからリザルト・進行復帰を確認する。
- 共通UIを利用する出陣・侵攻・共闘などは影響範囲に絞り、接続が保持されていることを確認する。
- 変更に必要な型検査・ビルドを実施する。問題のない全機能を何度も再検証しない。

## 8. 保存・提出と完了条件

実装、必要な検証、Git保存、専用Previewでの確認まで進める。mainマージ・Production公開はこの引継ぎには含めない。GAME03とProductionは変更しない。

最終提出には以下を含める。

- 保存ブランチ／SHA／PRがある場合はURL。
- 固定Preview URLと確認した戦闘経路。
- 通常戦闘・スキル命中・BURSTの確認画像または動画。
- 実施した検証結果と未完了事項。

「見た目のみ」「固定QA画面のみ」「演出が動くが実データに未接続」の状態を完成とはしない。未確認項目を完了と報告せず、残件を具体化する。過去スレッドの全再調査に時間を費やさず、本書・承認モック・最新コードに必要な範囲から着手する。
