## 実装・G2/P03契約

1. GAME03のraw-body HMAC署名、サーバーAuth.getUser、価格snapshot照合、支払済session確認、冪等DB付与、Stripe再取得、戻り先origin照合を保持。
2. G2正式4パック/6輝石にVIP480円を接続。VIP普通付与itemsは空。U09 game04_grant_vipのみが権利と初回100を付与する。
3. game04_billing_reserve_orderはuser row lock下で有効VIP・未確定VIP注文を拒否。既存requestは同じ注文へ戻す。通常パック通算上限は既存RPCに委譲。
4. game04_billing_grant_orderは既存billing_grant_orderとU09を同一transactionに置き、権利失敗時は注文確定/決済台帳もrollback。旧GRANTEDかつVIP未付与はrestore/checkout再試行で回復可能。
5. Stripe metadata.application=game04、冪等key=game04-sandbox-order。Webhookは他application/別DB注文に付与しない。DB照会障害は503再送、注文無し404と区別。
6. 通知台帳はevent_id/order/session/type/mode/state/試行数/時刻のみ保存。本文・顧客情報・例外テキストは保存しない。COMPLETEDは通知処理完了であり支払成功とは別。記録済でも最新Stripe状態を再確認し、DB冪等性で重複防止。
7. P03に合わせusers.id・game04_player_state.user_id・Auth UID一致、auth_method正一致、単一Googleまたは確認済email、非anonymousを購入条件とする。
8. cardのみCheckout作成。async_payment_failedも通知記録し最新session確認。unpaidはPENDING維持、Stripe session expired時だけ予約解放。cancel帰還のみで注文失効/付与せず、支払途中の同一注文を復旧可能にする。

## 現行DBとG2統合残件

現行DBは旧商品内容(beginner CASH1000/券各1/raid3、growth/awakening旧、diamond1030等)。現在のGAME04 catalog一致検証により販売拒否される。p02-catalog-candidate.sqlは正式11商品upsertのみで旧ID・注文snapshot・購入回数を削除/初期化しない。G2商品所有者が照合して適用する。

既存billing_grant_orderはpresentsとbilling_asset_lotsへ付与する。G2 BOXから正式state在庫・輝石walletへの受取、原資lot期限の交換先継承は未確認。P02が別途stateへ二重付与しない。U08/U09統合でパック全種・DIAMOND・EXP・選択魂・銭・券・薬の実受取と再読込を実証する。旧残高換算なし。

VIP定期30回/720h/696hと戦闘権利はU09、ジョブ起動はP06。120日は既存billing snapshot検証契約であり、法的適合・新たな正式期限承認を意味しない。正式期限変更ならU08/P04も同時調整。
