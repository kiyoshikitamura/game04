# 領土侵攻 UI 独立検証 2026-09-24

## 検証範囲と証拠の区分

`scripts/verify_game04_invasion_browser.cjs` を使用。実装本体の `TerritoryView`、`RedesignShell`、`Modal`、成功後の `RaidView` を `/qa/invasion-approved` で動かした。正式侵攻Masterを投影するが、所持数・主催EXP・開催成功/失敗は明示したオフラインfixtureである。DB/API、自然育成、実APIの再送・永続化の新規受入証拠とは区別する。

実行環境はChrome headless、viewport 390×844および390×568。画像decode・表示transition完了後に同一viewportの画面を撮影した。

## 確認内容

- 一覧→詳細→中央「侵攻確認」。CTA「侵攻する」、キャンセルは開催要求0回。
- 開始/中間/最終の各選択、選択枠、画像src・名前・敵Lv・HP/ATK/DEFを `createFormalInvasionMaster('TI01',()=>0)` の正式段階値と直接assert。共通HPを能力HPとして表示しない。
- 中間段階6は仮閲覧代表。正式な中間指定を確定せず画面/資料に仮を保持する。
- 所持0/必要Lv不足でも一覧・詳細へ進める。開始のみ非活性。
- 失敗fixtureは所持3のまま。同期2連打は1要求・所持3→2・既存共闘詳細へ遷移。
- 複数開催fixtureの2件目から正しいroom IDへ再開。
- 終了fixtureは開催枠0へ戻り、終了した侵攻→結果・報酬を確認→既存共闘詳細へ接続。
- 中央Dialogは低画面内に収まり、フッターの2CTAへ到達。背面shellのinert有効/解除を確認。
- Header/Footer、横幅、Footer本陣/出陣/武将/共闘/召喚の5件を確認。画像欠落・pageerrorなし。

## 内部修正・再検証

目視で見つかった開始/中間/最終の人物占有率不足、最終Lv折返し、一覧の顔と名前の重なり、Header Lvの誤配置、顔素材の枠外露出を表示担当へ差し戻し、修正後に撮影・機能検証を再実行した。背面操作抑止も再確認。

## 比較条件

モックの画像内数値・敵・城・開催枠は表示例。実装は正式素材/正式5城/12段階/主催仮FIXを優先し、モックの1/2開催枠や敵画像を固定採用していない。共通城背景は承認済み共闘素材を使用するため、個別城の実景ではない。上段モック/下段本体比較は列幅390pxに揃え、撮影画像を切り貼りで画面改変していない。

## 今回単独検証では閉じない項目

- 実APIの主催成功・再送・通信失敗非消費・永続化。本書の成功はfixtureでありサーバー成功を意味しない。前回共闘の実API記録は過去証拠として保持。
- 通常育成/行動力の自然な通し受入。
- 本陣/出陣/武将の全画面回帰。共有Modalのinertは侵攻で確認し、他画面の全操作完了には読み替えない。
