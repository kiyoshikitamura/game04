## DBG-046 模擬戦再生の先頭復帰

- 模擬戦はAPI戦闘開始要求ではなくcreateTutorialBattleによるローカル記録再生。IntegratedTutorialがstate全体をuseMemo依存にしていたため、60秒ごとのget_state/画面復帰等で同じ進行でも新resultを生成。useRecordedBattlePlaybackのresult変更効果が再生位置を0へ戻す。開始要求二重送信ではない再生側の確定経路。ユーザー端末の個別発生トレースは未取得。
- 修正：模擬戦を独立したTutorialPracticeへ分離し、同じユーザー/ステップのマウント中はuseState初期化で記録を保持。通常状態再取得・完了保存失敗で再生成しない。完了操作は同期refロックで二重要求を防ぐ。失敗時だけ再試行可能、成功後はサーバー保存された次ステップを表示する。
- 模擬戦自体に追加報酬の付与はない。武将・スキル加入は既存applyTutorialTransitionのstep一致/既所持判定を保持。APIは既存request receiptの同操作再試行に現在状態を返し、競合保存も既存制御を保持。進捗や報酬の巻戻しなし。
- 375/390：再生途中のstate再取得でframe不変、完了時連打で1要求、通信失敗でも勝利画面維持、再取得後再試行で次ステップへ、保存後reloadで模擬戦なし。既存tutorialドメイン検証で加入/初期装備/決定的模擬戦/再試行/一度限りの処理を確認。未完了の戦闘をページ全体reloadした場合は既存どおり未完了ステップから再生する。完了済み戦闘とは区別。
- 検証器 verify_b10_tutorial.cjs は実IntegratedTutorial/BattleViewと合成保存層を使用。サーバーへの実ユーザー操作なし。端末実機確認は配信後。
