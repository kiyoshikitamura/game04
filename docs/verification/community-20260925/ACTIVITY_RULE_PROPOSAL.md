## 4. 保存・重複・既存記録・表示

1. 新成果はサーバーの成功確定と同じトランザクションで記録する。画面到達、ボタンクリック、楽観更新を発生条件にしない。失敗・競合ロールバックは0件。
2. requestIdの再送抑制に加え、上表の成果キーにDB一意制約を設ける。別requestIdや複数参加者の並行精算でも同じ成果を複数生成しない。装備の別個体完成は別成果。
3. 新成果の既存状態からの一括生成はしない。適用後の確定遷移だけを対象とし、既存最大育成品・クリア済みエリアを再読込しただけで公開しない。SSR既存receiptの24時間投影というPR #35案は別扱いで維持。
4. 新成果も活動だけに掲載。全体への自動投稿は救援だけを維持。Home3件、展開表示、時系列の既存構成を維持し、独自の日次上限や投稿クールダウンは設けない。
5. 10連のSSR複数結果は個々のreceiptを保持し、同じ要求の表示を1行へまとめる案。再取得時も同じ表示グループIDを使い、結果を落とさない。救援まで束ねない。
6. 新成果は候補RPCと同じ24時間表示を推奨。これはDB保存期間の変更ではない。既存GAME04救援の表示期間は独自変更せず、終了済みルームへの遷移で誤って参加可能と見せない。
7. 公開対象は既存活動と同じゲーム利用者。匿名セッションの成果を認証していないことだけで除外しない。QA/test分類の除外はイベント時点で適用し、メール・課金額・保有残高は記録しない。
