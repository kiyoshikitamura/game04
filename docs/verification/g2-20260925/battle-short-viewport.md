# G2 U04/U05・Q02: 低高さの戦闘HUD

## 発見と根拠

親の本体390×568実戦闘では、敵立ち絵が約300pxを占有し、SPは見える一方で味方HUD全体が画面外だった。スクロールで到達可能なため操作不能とは区別するが、Battle Authority §13 の Header / Enemy / 共通SP・BURST / Party を「常時領域」とする要件、承認モックの「戦闘情報・操作に領域を優先」に適合しない。

原因はCSSの `.arena{height:clamp(380px,108vw,540px)}` が幅だけに追従して390px幅では421.2pxとなり、低高さでも同じ面積を取ること。味方portraitも25vw（97.5px）。スクロール共通ルールは維持する。

## 修正

`BattleView.module.css` のみ。高さ650px以下・幅540px以下の縦持ちに限定した上書き。

- arenaを画面高さに応じ180〜272pxへ再配分。568px高では190px。
- 味方portraitを54pxへ。5人の列数、名前/Lv/HP/状態/スキル、文字サイズ・操作サイズは維持。
- 360px幅での操作列の強制2段化を解除。ロゴだけ幅24%へ変更し、44px以上の再生操作は維持。
- 敵1〜3人の高さを確保。3人は短画面で3列に並べ、旧中央主敵/側面58%の重なりから生じるHUD・画像欠けを避ける。
- E独立レビューで短いカットイン上のBURST/スキル名と武将名の百分率bottom指定が接近する懸念を確認。文字サイズを維持し、武将名bottom8px・BURST文字bottom42px・スキル名bottom34pxへ分離した。
- 正式出陣65面の195Waveを照合し最大敵3人。共闘の現コードも本体1＋護衛2まで。旧4〜6人記録は従来2段とarena高さを維持し、情報を隠さずスクロールで閲覧する。この旧密集状態の全HUD常時表示は今回保証しない。
- 通常高さ、横向き、結果・詳細のスクロール、文字・操作サイズ、バトル計算・API/DBは変更なし。全体scaleやoverflowで情報を隠していない。

## 検証と限界

`node scripts/verify_game04_g2_battle_short_viewport.cjs` PASS。PostCSS構文、限定media、文字/ターゲット縮小・隠しなし、5列維持、65面最大敵数を静的確認。360/375/390幅×568高でarena190・portrait54となる。これはCSS指定値の確認であり、実際の画面内可視性や操作完了の証拠ではない。

親の専用Preview再配信後に本体で比較する。敵1/2/3、味方5人、長名・大数量、状態あり/なし、VIP操作あり、共有HPありを確認。3人編成だけで5人を受入済みにしない。画像crop・カットイン・実機/Safariは独立確認が必要。E独立CSSレビューを実施し、上記カットイン配置を是正。実画像の確認とは区別する。
