## 設計の中心

- 面内の比較では武将Lv・覚醒・装備の種類とLv・技LBを固定する。属性・配置・装備技の順番・支援・解除・SP供給・攻撃役へのBURST配分で結果が変わるかを確認する。
- 初期の確定加入5名を用いる。後半の未所持SSRやSSR最大装備を前提にしない。候補予算は最終Lv80・覚醒3・R装備Lv50・装備LB0・技LB5まで。最低育成値ではない。
- 最適解は検証候補中の200試行以上の全勝。次点60%前後、ギリギリ30%前後、ほぼ厳しい0%超〜10%、未勝利0%を別欄とし、実数を併記。段階が見つからない面に失敗編成を無理に作らない。全勝・未勝利を真の100%・0%と同一視しない。
- 異なる戦法の全勝候補＋60%以上の代替を基本の検査条件とする。装備したスキル名だけで「反撃」「解除」等を成立扱いにせず、中心技が試行の半数以上で発動することを確認する。個々の発動・付与・解除件数は各seedに保持する。この閾値は監査上の操作的定義であり、因果効果の完全証明ではない。
- 属性を替えただけの同系統は独立戦法に数えない。通常攻撃でSPを供給し、攻撃スキルを持つ役へBURSTを集める編成も検証する。スキル未装備は通常行動であり、BURST中に通常攻撃へ切り替える改変ではない。
- 3-1のDEF620単独案は撤回済み。550候補から複数戦法を評価し直し、後続面と同じ検査に掛ける。全敵DEF一律低下や共通ダメージ式変更は行わない。

## 試行と保存

探索81001〜81006、候補選定82001〜82020、初回独立検証84001〜84200。再調整の探索は85001〜85060・85501〜85520、独立検証は86001〜86200から1000刻みの別200seed。勝利したseedだけを抜き出さない。独立検証の失敗回はvalidation-v1／round-*として保持し、次の調整に使った場合はもはや独立評価ではないことを区別する。

全68面の最終固定入力と全seedの勝敗・行動・到達派・実ダメージ・SP・BURST・発動技・敗北理由を保存。圧縮ファイルはgzip JSON。通常の結果ハッシュはoutcome/reason/actions/waves/analysis/final-frameを対象とするsummaryHashであり、全フレームハッシュとは区別する。各面のsample-traceは全フレームを保存し、再生時に全体ハッシュを比較する。seedや入力を変更すると再生照合は失敗する。

探索中の中間全候補のフレームは保存対象にしない。最終探索・元設定の結果、採用案の全独立試行、調整履歴を保存する。報告の試行数は保存された対象を明記し、探索回数や重複コピーを加算して膨らませない。

再現:

```

```

REPLAY_ALL=1なら最終全seedのsummaryHashを再計算。通常は各編成の最初・最後のseedと各面の全フレーム例を照合する。正式バランス採用後にはAPIバンドルの再生成・入力照合・実機確認が別途必要。

## 入手と費用

economy-proposal.jsonは、現在面より前に確定受領できる各面1回の報酬とステージ／エリア任務を数える。武将・技・装備の育成を資産単位で累積し、同じLvまでの育成を毎面再課金しない。N装備からR装備への切替時は、既に使ったN装備育成費も消さない。異なる攻略法への切替に必要な技LB費も含む。

既存固定供給だけでは確保できない技・装備、武将覚醒に必要な汎用R魂、EXP・銭・技素材を、前面初回報酬へ追加する案として分離する。ガチャ当選を確定入手に数えず、その面自身の初回報酬は使わない。日次・ログボ・育成任務・既存所持資産は未計上なので、資源追加量はこの保守的な一本道の供給案であり、全ユーザーの実不足や唯一の最小額ではない。

通常クエストの魂ドロップ全68面に初期5名のIDは含まれない。覚醒魂を「前面周回で集める」とする説明は不可。現行報酬のみで保証できないため、汎用R魂の確定追加を承認対象にする。

追加EXP/銭案を採用する経路では必須育成周回0回とする。追加しない比較も前面の検証済み編成での勝利回数・行動力を記載するが、技・装備・覚醒魂の保証経路にはならない。素材待ちを主な攻略にしないための報酬提案で、共通育成式を安くする変更ではない。

エリア1/2各5面、1-1/1-3加入、1-2/1-4技と編成ガイド、1-5初期デッキ＋BURST、エリア任務無償輝石300を保持。2-1/2-2の初敗北・見直し導線の実機受入は既存担当と連携する。勝率表は検証済み再挑戦編成の結果であり、無育成初見の全勝を要求しない。
